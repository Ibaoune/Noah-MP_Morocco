# NorthMor 1Yr_2016 Experiments Workflow

This directory contains the automated daisy-chain workflows to run the Open Loop (OPL) and Data Assimilation (DA) experiments for the year **2016**.

The infrastructure uses a dynamic, robust approach (adapted from the spin-up workflow).

## Initialization Strategy

Because the Data Assimilation (DA) run requires **both** a surface model restart (`LIS_RST`) and a perturbation restart (`LIS_DAPERT`), but the spin-up only generated a surface model restart, we use a 3-step strategy:

### 1. Generating Initial Perturbations (`ens_opl_2015/`)
- Takes the spin-up restart from the end of 2014 (`LIS_RST_NOAHMP401_201501010000.d01.nc`).
- Runs an Ensemble Open Loop for the entire year of **2015** (State mode: `restart`, Perturbation mode: `coldstart`).
- This spins up the ensemble perturbations for 1 full year.
- Upon completion, the script automatically copies the resulting `LIS_RST` and `LIS_DAPERT` files (dated `201601010000`) into the `assim/restarts/surf/` and `assim/restarts/pert/` directories.

### 2. Running the Data Assimilation (`assim/`)
- Starts on **2016-01-01** using the fully spun-up state and perturbation restarts generated by `ens_opl_2015`.
- Both state and perturbation modes are set to `restart`.
- Runs continuously month-by-month through 2016, daisy-chaining itself by passing along the two restart files.

### 3. Running the Open Loop (`opl/`)
- The OPL does not require perturbations.
- It starts on **2016-01-01** taking the surface restart directly from the 10-year spin-up (`LIS_RST_NOAHMP401_201601010000.d01.nc`).
- Runs continuously month-by-month through 2016.

## Execution

To launch the experiments, submit the respective `job.sh` scripts.

1. **First**, generate the perturbations for 2015:
   ```bash
   cd ens_opl_2015
   sbatch job.sh
   ```

2. **Second**, once `ens_opl_2015` completes successfully (the restart files will appear in `assim/restarts/`), you can start DA:
   ```bash
   cd ../assim
   sbatch job.sh
   ```

3. **In parallel**, you can start the OPL run immediately, as it only depends on the main spin-up:
   ```bash
   cd ../opl
   sbatch job.sh
   ```

All logs, generated configurations, and outputs are dynamically sorted into folders by year/month.
