4. SOURCE CODE BUG PATCHES (To resolve compile errors with GCC 13/14)
--------------------------------------------------------------------------------
To resolve compilation conflicts between legacy LISF code and modern GCC compilers, two code changes were implemented:

1. LIS Intrinsics conflict:
   - File: lisf/lis/core/LIS_misc.h
   - Change: Commented out custom macro redefinitions of standard Fortran intrinsics (get_command_argument and command_argument_count) to let the compiler use built-in GNU Fortran intrinsics.

2. LDT System intrinsic conflict:
   - File: lisf/ldt/WSF_OPL/LDT_wsf_oplMod.F90 (around line 555)
   - Change: Commented out the 'external :: system' statement. This tells the compiler that 'system' is an intrinsic subprogram rather than an external user-written routine (resolving unresolved external symbols at link-time).

7. STEPS FOR 3-MONTH SIMULATION (WITH AND WITHOUT ASSIMILATION)
--------------------------------------------------------------------------------
To run your first 3-month test simulation (e.g., June 1, 2020 to August 31, 2020), follow these steps:

STEP A: Download Meteorological Forcing & Satellite Observations
1. Select a 3-month window: e.g., 2020-06-01 to 2020-08-31.
2. Download/Prepare Met Forcing: MERRA-2, ERA5, or GPM IMERG for the region.
3. Download/Prepare Soil Moisture observations (e.g., SMAP L3 passive or ESA-CCI) for the same period.

STEP B: Generate Model Parameters via LDT
1. Edit 'ldt.config' and specify:
   - The Allal El Fassi Basin grid parameters (0.01 deg resolution).
   - Paths to your static data directories (soils, topography, land cover).
2. Run LDT:
   ./LDT ldt.config
3. This creates 'lis_input.d01.nc' containing the parameters on your exact 1 km grid.

STEP C: Configure and Run LIS - Open-Loop (OPL) Simulation
1. Create a config file 'lis.config.opl'.
2. Set running mode:
   LIS running mode:                 "retrospective"
   Number of data assimilation sources: 0
   Data assimilation sources:        none
3. Set simulation dates:
   Starting year:                    2020
   Starting month:                   06
   Starting day:                     01
   Starting hour:                    00
   Starting minute:                  00
   Starting second:                  00
   Ending year:                      2020
   Ending month:                     08
   Ending day:                       31
   Ending hour:                      23
   Ending minute:                    45
   Ending second:                    00
4. Specify input parameter file:
   LIS parameter table filename:     ./lis_input.d01.nc
5. Set output directory:
   LIS output directory:             ./OUTPUT_OPL
6. Run the Open Loop simulation:
   mpirun -np 4 ./LIS lis.config.opl

STEP D: Configure and Run LIS - Data Assimilation (DA) Simulation
1. Create a config file 'lis.config.da'.
2. Set running mode to retrospective with EnKF assimilation:
   LIS running mode:                 "retrospective"
   Number of data assimilation sources: 1
   Data assimilation sources:        "SMAP passive SM" (or "ESA-CCI passive SM")
   Data assimilation method:         "EnKF"
3. Configure ensemble size and perturbations (required for EnKF):
   Number of ensembles:              12  # recommended minimum test size
   Perturb met forcing:              .true.
   Perturb state:                    .true.
   Met forcing perturbation config:  forcing_attribs.txt
   State perturbation config:        state_attribs.txt
4. Set output directory:
   LIS output directory:             ./OUTPUT_DA
5. Run the Data Assimilation simulation:
   mpirun -np 12 ./LIS lis.config.da

STEP E: Evaluate & Compare using LVT
1. Create 'lvt.config' to compare OUTPUT_OPL vs OUTPUT_DA against independent satellite observations:
   - Set runmode: "Verification"
   - Under LIS forecast directory, point to: `./OUTPUT_OPL` and `./OUTPUT_DA`
   - Under Observation directory, point to: your independent satellite observations (e.g. soil moisture, LAI, ET)
2. Run LVT:
   ./LVT lvt.config
3. Analyze the generated verification metrics (bias, RMSE, correlation) to evaluate the impact of data assimilation.

STEP F: Custom Python Visualizations
1. A dedicated Python script (`scripts/plot_da_comparison.py`) allows you to automatically parse NetCDF files generated by LIS.
2. Ensure you have enabled the `LAI` output parameter in `configs/MODEL_OUTPUT_LIST.TBL` (set the first column to 1).
3. Run the analysis script to extract multi-month (e.g., JJA 2020) Soil Moisture, Evapotranspiration, and LAI.
   python3 scripts/plot_da_comparison.py
4. Time-series and spatial maps representing the impacts of assimilation (`DA - OPL`) are exported directly to `experiments/plots/`.
